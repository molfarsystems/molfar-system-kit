Питання про правила спільноти та рішення щодо участі Reddit залишаються відкритими. За замовчуванням залишається гілка А (пропуск Reddit).
-   **Тегування та знімок запуску:** Збережено чотири UTM джерела: `github`, `discord`, `telegram`, `x`. `utm_campaign` — `kit-launch`, `utm_medium` — `social`. `utm_content` змінюється щотижня (`w1`, `w2`, `w3`, `w4`). Додано новий крок у тиждень 1: знімок трафіку GitHub після публікації.
-   **Прогалини:** Не оцінено редагування README, базовий знімок, щотижневі перевірки, фінальна перевірка, відповіді та виправлення сайту. Залишається відкритим питання про те, хто відповідає на обговорення GitHub під час відсутності власника.

Раунд 3 — підсумок модератора
У цьому раунді були надані додаткові уточнення та оцінки.
-   **Розміщення FAQ та резервний варіант:** За замовчуванням FAQ розміщується у README з прикріпленою приміткою. Якщо власник не може редагувати README або закріплювати обговорення з телефону, FAQ та примітка про затримку відповідей розміщуються безпосередньо в оголошенні GitHub Discussions та на форумі Discord `feedback`. Оцінки часу: редагування README — 20–30 хв; резервний варіант додає 10–15 хв.
-   **Посилання у Twitter:** Пости 1/–5/ та 7/ не містять посилань. Пост 6/ містить звичайну URL-адресу репозиторію. Закріплена відповідь під 1/ містить посилання на Play, вебсайт та репозиторій. Щотижневе оновлення закріпленої відповіді з новим `utm_content` є новим повторюваним кроком (без оцінки часу). Залишається неперевіреним, чи дозволяє X закріплювати відповідь.
-   **Reddit:** Reddit Community Builder визначив сторінки, які власник має прочитати перед публікацією (Правила Reddit, Політика контенту, сторінка спаму, керівництво з самореклами та правила цільового сабреддіта). Було зазначено, що конфлікт між вимогою щодо вікна відповідей (4–6 годин) та правилом "відсутність щоденної присутності" власника посилює рішення про **виключення Reddit з цих 4 тижнів**.
-   **Оцінки часу:** Analytics Reporter надав оцінки часу для базового знімка (30 хв), знімка запуску (10 хв), щотижневої перевірки (15 хв) та фінальної перевірки (15 хв). Зазначено, що знімок запуску доповнює крок 5.
-   **Загальна спроможність:** Орієнтовні витрати часу фахівців за тиждень 1 становлять 3.2–3.3 год (або 3 год з резервним варіантом), що наближається до 4-годинного ліміту. Тижні 2–4: близько 1.3 год, 1.6 год та 1.8 год відповідно.

РІШЕННЯ
-   **Повідомлення, тегування, розкриття:** Використання єдиних описів від Content Creator. Єдина назва кампанії `kit-launch` з посиланням від Analytics Reporter. Розкриття інформації про розробника: соло-розробник з України, працює з Claude.
-   **Розміщення FAQ:** За замовчуванням FAQ розміщується у README репозиторію.
-   **Розміщення оголошення:** Оголошення залишається у GitHub Discussions та посилається на README FAQ.
-   **Примітка про відповіді:** Прикріплена примітка про можливі затримки відповідей розміщується в GitHub Discussions.
-   **UTM-параметри:** UTM джерела: `github`, `discord`, `telegram`, `x`. `utm_campaign` — `kit-launch`, `utm_medium` — `social`. `utm_content` змінюється щотижня (`w1`, `w2`, `w3`, `w4`).
-   **Посилання:** URL репозиторію залишається звичайним. Тегуються посилання на вебсайт та Play Store.
-   **Послідовність дій у тиждень 1:** Спочатку базовий знімок, потім публікація постів, потім знімок запуску.
-   **Запис даних:** Для порожніх рядків Play та UTM сайту записувати "not yet" (ще ні), для порожньої комірки GitHub після довгої перерви — "lost" (втрачено).
-   **Reddit:** За замовчуванням Reddit виключено з цих 4 тижнів кампанії.
